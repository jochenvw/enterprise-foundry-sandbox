# Operations

## Add a new central model deployment

1. Add a new `Microsoft.CognitiveServices/accounts/deployments` resource in
   `infra/modules/foundry-central.bicep` (or parameterize a second deployment).
2. Expose its name as a module output.
3. Add an APIM named value mapping a new alias to the deployment, and update the alias
   mapping in `infra/policies/team-api-policy.xml`.
4. Re-run `./scripts/validate.sh` then `./scripts/deploy.sh`.

The alias→deployment indirection means callers keep using stable aliases
(`enterprise-fast`, `enterprise-reasoning`) while the platform changes the backing model.

## Add a new team

1. Append the team key to `teamNames` in `infra/main.parameters.dev.json`
   (e.g. `"team-c"`).
2. Add a spoke address space parameter and a `network-spoke` + `foundry-team` +
   `foundry-team-data` + `rbac-team` module block in `infra/main.bicep` following the
   Team A/B pattern. APIM products/APIs/subscriptions/policies are generated by the
   `for ... in teamNames` loops, so they extend automatically.
3. Validate and deploy.

## Adjust token quotas

Change `teamTokenLimitPerMinute` in the parameters file (per-team TPM). For per-team
differentiation, pass distinct limits when calling the APIM module, or move the limit to
a per-team named value referenced by the policy.

## Rotate APIM subscriptions (fallback auth)

Team isolation uses APIM subscriptions (`sub-team-a`, `sub-team-b`). To rotate a key:

```bash
az apim subscription regenerate-key \
  --resource-group <hub-rg> --service-name <apim-name> \
  --subscription-id sub-team-a --key-kind primary
```

## Inspect logs

- **Application Insights** (APIM logger): request metadata, latency, status, traces from
  the policy `<trace>` (source `enterprise-foundry`).
- **Log Analytics**: diagnostic settings from APIM, Foundry accounts, Storage, Cosmos,
  Search, and Key Vault.

Example KQL (token metrics emitted by the gateway appear as customMetrics in App Insights):

```kusto
customMetrics
| where name == "Total Tokens" or name startswith "enterprise-foundry"
| extend team = tostring(customDimensions.team), alias = tostring(customDimensions.modelAlias)
| summarize tokens = sum(value) by team, alias, bin(timestamp, 1h)
```

## Trace a model call from team route to central backend

1. Find the request in Application Insights by `request-id` (returned/traced by APIM).
2. The policy trace line records `team`, `api`, `op`, `alias`, `deployment`, `status`,
   and `duration-ms`.
3. Correlate with central Foundry diagnostics in Log Analytics for the backend call.

## Estimate cost by team

Token metrics are dimensioned by `team`, `modelAlias`, and `centralDeployment`. Sum
`Total Tokens` per `team` over a period and multiply by the model's per-token price.
Because all teams share one central deployment, gateway token metrics are the primary
per-team attribution signal.
